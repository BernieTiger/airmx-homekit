# 部署指南

> 每一步都有验收标准。**没通过验收不要进入下一步**，否则问题会累积到最后无法定位。

---

## 前置条件

| # | 条件 | 为什么必须 |
|---|---|---|
| 1 | 一台**常开**的机器（NAS / 树莓派 / Linux 主机） | DNS 指向它，机器关机设备就失联 |
| 2 | 已装 Docker 与 Compose 插件 | 不用 Docker 也可以，见文末 |
| 3 | 能进路由器改 **DNS** | 整个方案的地基 |
| 4 | 加湿器与主机**同一局域网** | 跨网段需要在 `.env` 放行 |

**不需要**：公网 IP、域名、云服务器、Apple 开发者账号。

---

## 步骤 1：获取代码

```bash
git clone https://github.com/<repo>/airmx-homekit.git
cd airmx-homekit
```

**验收**：`ls hap/ airmx_gateway/ bridge/ scripts/` 四个目录都在。

---

## 步骤 2：生成配置

```bash
./scripts/bootstrap.sh
```

脚本会做四件事：
1. 检查 Docker 环境
2. 随机生成 32 位管理令牌
3. 写入 `secrets/admin_token` 与 `secrets/master_key`
4. 从模板生成 `deploy/.env`

**验收**：

```bash
ls -l secrets/ deploy/.env
grep AIRMX_BRIDGE_TOKEN deploy/.env   # 应该有 32 位值，不是空
```

**失败分支**

| 报错 | 处理 |
|---|---|
| `未找到 docker compose` | 装 compose 插件，别用已废弃的 `docker-compose` |
| `Permission denied` | `chmod +x scripts/bootstrap.sh` |

---

## 步骤 3：启动

```bash
docker compose -f deploy/compose.yaml up -d
docker compose -f deploy/compose.yaml ps
```

**验收**：四个服务都是 `running`。

```bash
curl -s localhost:25888/health
```

期望：

```json
{"mqtt_connected": true, "device_count": 0, "devices_with_key": 0, ...}
```

`device_count: 0` 是正常的——设备还没连上来。

**失败分支**

| 现象 | 原因 | 处理 |
|---|---|---|
| 端口被占用 | 冲突 | 改 `.env` 里对应端口 |
| `mqtt_connected: false` | mqtt 没起来 | `docker compose logs mqtt` |
| 报 `AIRMX_BRIDGE_TOKEN is required` | 没跑 bootstrap | 回步骤 2 |

---

## 步骤 4：配置 DNS（最容易跳过）

路由器后台找到 DNS 转发 / 本地 DNS，加两条：

```
i.airmx.cn    → <本机IP>
awm.airmx.cn  → <本机IP>
```

**验收**（用**另一台**设备测，别在本机测）：

```bash
dig +short i.airmx.cn @<路由器IP>
```

返回本机 IP 才算成功。

**失败分支**

| 现象 | 原因 | 处理 |
|---|---|---|
| 返回公网 IP | 路由器不支持单域名转发 | 用 dnsmasq，或换支持的路由器 |
| 改完设备仍不出现 | 设备缓存了旧解析 | **断电重启设备**，不是重启服务 |
| 部分设备生不生效 | 设备用了硬编码 DNS | 在 DHCP 里强制下发 DNS |

然后等 1–2 分钟，再查一次：

```bash
curl -s localhost:25888/devices
```

**验收**：出现设备条目，`online: true`，`has_key: true`。

> `has_key` 从 false 变 true 最多需要 60 秒（bridge 的密钥同步周期）。耐心等，不要重启。

---

## 步骤 5：配对

家庭 App → `+` → 添加配件 → 输入 `deploy/.env` 里的 `AIRMX_HAP_PINCODE`。

**验收**：

```bash
TOKEN=$(grep AIRMX_BRIDGE_TOKEN deploy/.env | cut -d= -f2)
curl -s -H "Authorization: Bearer $TOKEN" localhost:51827/status | python3 -m json.tool | head -30
```

期望看到：

```json
{
  "paired_clients": 1,
  "accessories": [{"name": "...", "online": true, "available": true}]
}
```

**失败分支**

| 现象 | 原因 | 处理 |
|---|---|---|
| App 搜不到配件 | mDNS 出不去 | 确认 hap 是 `network_mode: host` |
| 搜到但配对失败 | 配对码格式错 | 必须是 `xxx-xx-xx` |
| 配对后无响应 | 见 `docs/04` | 先查 `available` |

---

## 步骤 6：全量验证

```bash
TOKEN=$(grep AIRMX_BRIDGE_TOKEN deploy/.env | cut -d= -f2)
echo "--- 设备 ---"
curl -s localhost:25888/devices | python3 -m json.tool
echo "--- 桥接 ---"
curl -s localhost:25888/health
echo "--- 配件 ---"
curl -s -H "Authorization: Bearer $TOKEN" localhost:51827/status | \
  python3 -c "import sys,json;d=json.load(sys.stdin);print([(a['name'],a['available']) for a in d['accessories']])"
```

六项全过才算成功：

| 项 | 期望 |
|---|---|
| 设备在线 | `online: true` |
| 有密钥 | `has_key: true` |
| MQTT 连通 | `mqtt_connected: true` |
| 配件可用 | `available: true` |
| 已配对 | `paired_clients >= 1` |
| 能控制 | 在 App 里开关一次，设备有反应 |

## 不用 Docker 的路径

适合已有 Python 环境的场景，但要自己管三个进程。见 `skill/references/deploy.md` 的「路径 C」。

不推荐新手走——依赖顺序、环境变量、日志分散，排查成本高。

---

## 升级与备份

**升级**

```bash
git pull
docker compose -f deploy/compose.yaml up -d --build
```

升级不会丢配对：`data/hap.state` 保存着配对密钥，只要这个文件在，
`paired_clients` 就会保持。

**备份**：只需要备份两个东西

```
data/hap.state     配对信息（丢了要重新配对）
deploy/.env        你的配置
```

`secrets/` 丢了会导致 bridge 和 hap 的 token 不匹配，重跑 bootstrap 即可（但要重启全部服务）。
