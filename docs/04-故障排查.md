# 故障排查（速查版）

详细版见 `skill/references/troubleshooting.md`。这里只列最常见的问题与一句话解法。

## 按现象索引

| 现象 | 最可能的原因 | 一句话解法 |
|---|---|---|
| 设备一直不出现 | DNS 没生效 | `dig i.airmx.cn` 看是否返回本机 IP |
| 设备 Wi-Fi 灯快闪 | DNS 指回公网 | 改路由器 DNS，然后**断电重启设备** |
| 家庭 App 显示无响应 | IID 变了，或状态文件写不进 | 查 `/status` 的 `available`；服务结构改回原样 |
| 配对全丢 | `data/hap.state` 没保住 | 检查 `data/` 挂载与权限 |
| 改了代码不生效 | 容器没真重启 | `docker compose up -d --force-recreate hap` |
| 开关名是「开关 2」 | iOS 没刷新 | 重启一次 hap，让配置版本 +1 |
| 调目标湿度风扇不动 | 设备固件不重算 | 等 25 秒（代码会自动 0→1 往返） |
| 指令返回 ok 但没生效 | 设备静默丢弃 | 读回状态确认，别信回执 |
| 连发两次只有第一次生效 | bridge 10 秒节流 | 两次操作间隔 >10 秒 |

## 三层定位法

```
家庭 App 不显示      → L4（hap ↔ HomeKit）
App 显示但数值不动    → L3（bridge ↔ hap）
数值不对但设备正常    → L2（gateway 解析）
设备根本不出现        → L1（DNS）
```

## 一条命令看全貌

```bash
TOKEN=$(grep AIRMX_BRIDGE_TOKEN deploy/.env | cut -d= -f2)
curl -s -H "Authorization: Bearer $TOKEN" localhost:51827/status | python3 -m json.tool
```

## 排障三原则

1. **先定位层级，再动手改**——不要看到"无响应"就重装配对
2. **回执不可信，读回才算数**——设备会静默丢弃指令
3. **改一处，验一处**——同时改两个变量，出问题无法归因
