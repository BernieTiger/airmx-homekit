# 功能映射与取舍

HomeKit 的服务与特征是一套封闭的语义。设备真实能力往里塞，一定会损失。
本文把每一处损失写清楚，避免用户误以为是 bug。

---

## 完整映射表

| 设备能力 | HomeKit 承载 | 实际效果 | 损失 |
|---|---|---|---|
| 开关机 | `Active` | 主磁贴开关 | 无 |
| 手动 / 自动 | `TargetHumidifierDehumidifierState` | 顶部档位切换 | 自动档下 iOS 隐藏目标湿度滑块 |
| 目标湿度 | `RelativeHumidityHumidifierThreshold` | 水罐拖动 | 无 |
| 当前湿度 | `CurrentRelativeHumidity` + 独立 `HumiditySensor` | 图形 + 数字 | 重复挂了两个，为了拿到数字 |
| 温度 | 独立 `TemperatureSensor` | 温度卡片 | 无（HAP 主服务无温度特征） |
| 风量 | 独立 `Fanv2` | 滑块 | 主服务上的 `RotationSpeed` iOS 不渲染，只能单挂 |
| 水位 | ❌ 无服务 | 看不到 | HAP 没有水位服务，`FilterMaintenance` 也不渲染 |
| 睡眠模式 | 独立 `Switch` | 开关 | 占用一个开关位 |
| 负离子 / 清洁提醒 / 接近感应 | 独立 `Switch` | 开关 | 同上，且状态行会出现多条"已打开电源" |
| 童锁 | `LockPhysicalControls` | 无界面 | 特征在，iOS 不画控件 |

---

## 三个"HomeKit 做不到"

### 1. 水位

HAP 的服务清单里**没有水位传感器**。唯一能承载百分比的是 `FilterMaintenance.FilterLifeLevel`，
但实测 iOS 连这张卡都不渲染。

**结论**：Home App 里永远看不到水位。

**替代方案**：`hap` 额外提供一个 Web 看板（`/status` 与 `/`），手机浏览器打开即可看完整数据。

### 2. 自动档下调目标湿度

iOS 认为"自动模式下目标由设备决定"，所以在该档位隐藏目标湿度滑块。

这是苹果的设计，所有加湿器都一样，无法绕过。

**替代方案**：先切「加湿」档调好目标，再切回「自动」。或者在自动档直接用 Siri 说目标值。

### 3. 多档模式的完整还原

机身按钮有 M / 50 / 45 / 40 / 睡眠 五档。但 50/45/40 不是模式，是**目标湿度预设**。

**结论**：HomeKit 里只有「加湿 / 自动」两档 + 一个睡眠开关，这是设备真实能力的完整映射。

## 刻意的减法

### 不做假开关

APK 里有 `uv`、`delayOffTimer`、`electrolysis` 等字段，但真机写入无效
（写 0 仍回 1，说明是能力标志）。这些一律不暴露。

**判断标准**：如果一个功能只能做成"按了没反应的开关"，宁可不做。

### 默认档位可调

`AIRMX_HAP_PROFILE` 控制暴露多少开关：

| 档位 | 内容 |
|---|---|
| `minimal` | 主控件 + 温湿度 + 风量，无附加开关 |
| `standard` | 加睡眠模式 |
| `full` | 加负离子 / 清洁提醒 / 接近感应 |

**为什么做成可配置**：每多一个开关，配件页就多一张大卡片，状态行也多一条"已打开电源"。
不是所有人都愿意用界面噪声换功能。

## 已知的行为怪癖（不是 bug）

| 现象 | 原因 |
|---|---|
| 自动档下改目标后要等约 25 秒风扇才变 | 设备固件不重算，代码要做 0→1 往返补偿 |
| 降速比升速慢（45 秒 vs 15 秒） | 设备为避免频繁启停，下行更保守 |
| 配件名下的状态行重复"已打开电源" | 每个 Switch 服务各贡献一条，iOS 用通用措辞 |
| 首次配对后开关名显示「开关 2」 | iOS 缓存，重启一次 hap 触发刷新即可 |
| 设备面板显示 M 但实际在自动 | 面板只有 5 个显示位，没有"自动"档 |
