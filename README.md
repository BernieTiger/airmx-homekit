# 秒新 AirMX 加湿器 · 本地化 HomeKit 接入

> 厂商已经停止运营，官方 App 与云端全部下线。但这台机器本身还是好的——
> 这个项目让它在没有云的情况下继续工作，并接入 Apple 家庭。

---

## 背景：一批被留在原地的设备

秒新（AirMX）已经停止运营，官方服务器关停，App 无法登录。

于是用户手里的 AirWater A3 / A3S / A5 变成了**数字孤儿**：

- 硬件完好：风机、水泵、雾化、温湿度传感器、水位检测都正常工作
- 软件失效：App 打不开，云端指令通道消失，自动化全部失效
- 只剩机身按键：几个档位、开关机，别的什么都做不了

这些机器当年售价不低，做工和加湿效果到现在依然能打。因为厂商没了就把它们当废品处理，
实在可惜——**它们缺的不是功能，只是一条能走通的控制链路。**

这个项目补的就是这条链路。

---

## 做了什么

把原来依赖厂商云的三段链路，整体搬到本地：

```
设备  ──DNS 劫持──>  本地网关  ──MQTT──>  bridge  ──HTTP──>  HomeKit 桥接  ──> 家庭 App
        (指向本机)   (复现注册/签名)      (状态与指令)        (语义翻译)        (Siri/自动化)
```

1. **DNS 劫持**：让设备把 `*.airmx.cn` 解析到你的局域网地址，它以为自己还在连官方服务器
2. **本地网关**：复现设备侧的注册、心跳、指令签名，让设备愿意接受指令
3. **HomeKit 桥接**：把设备能力翻译成 Apple 家庭理解的语义，用 Siri 和自动化控制

全程**不依赖任何外部服务**，局域网内可用，数据不出家门。

---

## 它是什么 / 不是什么

**是**

- 一个让已购硬件在厂商停服后继续可用的方案
- 一套可以照着复现的部署流程，含完整的逆向排查思路
- 一个可复用的 HomeKit 桥接层（换设备只需改映射表）

**不是**

- 不是刷机、不是改固件。设备一个字节都没动，它仍然认为自己在连官方服务器
- 不是云端替代服务，本项目不提供任何托管
- 不能让你在外网直接控制（除非你自己做内网穿透，那部分不在本项目范围）
- 不保证所有型号/固件版本都能跑通

## 快速开始

### 前置条件

1. 一台**常开**的机器（NAS / 树莓派 / Linux 主机），已装 Docker 与 Docker Compose
2. 能进路由器改 **DNS** 设置（这是整个方案的前提）
3. 加湿器与这台机器在**同一局域网**

### 三步

```bash
# 1. 下载
git clone https://github.com/<your-name>/airmx-homekit.git
cd airmx-homekit

# 2. 生成配置：随机 token、secrets、.env
./scripts/bootstrap.sh

# 3. 启动
docker compose -f deploy/compose.yaml up -d
```

启动后还有两步**必须做**，否则设备不会连过来：

4. 路由器 DNS 把 `*.airmx.cn` 指向这台机器的 IP（见 `docs/03`）
5. 家庭 App → `+` → 输入配对码（`.env` 里的 `AIRMX_HAP_PINCODE`）

**每一步的验收标准见 [`docs/03-部署指南.md`](docs/03-部署指南.md)。**
动手前请先读 [`docs/01-逆向排查思路.md`](docs/01-逆向排查思路.md)，它解释了为什么必须做 DNS 劫持。
